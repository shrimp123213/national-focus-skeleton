# 現有腳本加上分期：UI 樣品

入口：[分期國策-現有介面樣品.html](../分期國策-現有介面樣品.html)。直接以瀏覽器開啟即可，也可從 <http://127.0.0.1:4186/> 開啟。

這份樣品修正上一版另做獨立介面的偏差。它直接編譯目前 `src/ui.ts`、`src/style.css`、`FocusController`、引擎、布局、圖示及各原有面板，沿用 v0.13.4-skeleton 的外觀與互動。沒有修改 `src/` 或 `dist/`。

## 與原版的差異

1. 國家資訊列下方新增期別列：當前期名、自動換期開關、往期摘要入口。
2. 原本的國家管理列也提供同一個換期開關。
3. 承接節點加上「前期承接」小標籤，原詳情抽屜顯示進度／成果保留說明。
4. 往期摘要使用原本的對話框樣式，只顯示時間與文字摘要。
5. 在既有「測試操作」加入兩種情境與演示換期操作；原「更新局勢」按鈕在此樣品呼叫固定離線情境。

懸浮球、國家列、路線導覽、搜尋、卡片、連線、拖曳縮放、詳情抽屜、開始／暫停／改選、事件紀錄、設定面板均沿用現有程式。測試操作的「故事時間 ＋7 日」仍走正式引擎，可繼續執行承接的國策。

## 操作順序與人工驗收

**狀態：待人工驗收。** 未使用 computer use 或瀏覽器自動化進行 UI 驗收。

1. 開啟後確認是原腳本的面板；關閉面板後用原懸浮球重開。
2. 展開原本的「測試操作」，選「載入：局勢突變情境」，點「推進事件／演示換期」。期別改為第二期〈災厄越過國境〉，A04 糧運國策保留 18／30 日；原卡片與詳情出現承接提示。
3. 開啟「往期摘要」，確認只有時間與摘要。使用原「事件紀錄」查看持續的船位之爭；再推進演示事件，不應產生第二份歷史或複製事件。
4. 按兩次「故事時間 ＋7 日」，承接國策應完成。用原詳情按鈕開始新期的救援許可，再推進 7 日，確認原操作可接續使用。
5. 載入「議程完成情境」並演示換期，確認以已完成的 A12 貿易新秩序作起點，不重啟工期；舊債事件繼續。
6. 重設，關閉自動換期再推進。確認仍是第一期，事件進展照常更新。國家列與國家管理中的開關需同步。
7. 在桌面及窄視窗確認新增期別列沒有遮擋原畫布／詳情／測試操作；測試原拖曳、縮放、搜尋、路線收合及事件篩選。

## 樣品邊界

- 只有帝國的兩組固定情境；國策是設計樣稿，不是 API 生成。API 與模型連線仍由原 DemoPlatform 阻擋，資料存在記憶體，不接酒館或 MVU。
- 自動換期的語義判斷、正式資料遷移、匯入／匯出期別格式尚未實作。期別摘要與開關存在樣品平台，不混入正式 StateSchema。原匯出功能不含樣品期別資料。
- 「推進事件／演示換期」只模擬固定劇情變化，不增加故事日；「＋7 日」才會增加國策工期。歷史時間使用樣稿中的示意日期。
- 若先改選其他主國策，固定劇情不會擅自清掉該國策；頁面提示重設對應情境。另行匯入／修改的樹不適用這組固定演示。
- 每期 12 項，第二期包含 1 項承接、11 項新增。承接項是否計入正式生成預算，以及獨立新議程的前置安排，仍是設計待定事項。
- 國策完成成果在這份樣品中以制度能力呈現；數值、工期、外部成果與新期內容均為示意，未宣稱完成完整分期引擎。

## 重建與開啟

```powershell
& 'C:\Program Files\nodejs\node.exe' 'F:\命一串\national-focus-skeleton\docs\period-preview\build.mjs'
& 'C:\Program Files\nodejs\node.exe' 'F:\命一串\national-focus-skeleton\docs\preview-periods.mjs'
```

`build.mjs` 優先使用骨架版的 node_modules，沒有時使用同工作區原版 `national-focus/node_modules`。它在記憶體中對原 UI 加入少量分期顯示與演示入口，追加 `extra.css`，型別檢查後打包成單一 HTML；不覆寫正式來源。插入位置不符時會停止建置，避免來源更新後靜默套錯位置。`build-info.json` 記錄使用的 UI／CSS 雜湊。

已執行：完整樣品及引用程式的 TypeScript 檢查、打包、正式 StateSchema 驗證、兩種情境的換期／開關保護／事件延續、進度與既有效果紀錄保留，以及原引擎完成承接國策後開始並推進新國策的受控測試。視覺與真實酒館驗收未執行。
