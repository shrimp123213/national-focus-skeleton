## 骨架版與 v0.11.1 的差異

標準以上的規模改為「骨架先行」，小型不變（一次請求）：

1. **骨架（1 次請求）**：模型先排出整棵樹的每一個國策，但只寫結構與規則：名稱、分支、要點、前置、互斥路線與鎖定時機（開始時或完成時）、轉折國策與它的國家行動、產生或撤銷的能力、穩定度與戰爭支持度的增減，以及開始、推進中、完成三種條件。所有結構規則都在這一步檢查，不符只重寫骨架。
2. **填寫（每批 1 次請求）**：把骨架分批交給模型寫描述、理由、工期、投入、承諾、互斥理由與新聞內文。一批可以跨分支，每批上限是生成任務的「每批填寫國策數」（v0.13.3 前在 API 預設；原「每次最多國策數」，預設 25，0 為整棵樹一批）。結構一律取骨架，模型改不了。
3. **逐項接受**：一批裡通過的國策立刻保留；缺漏或不合格的，最後集中補填，只送那些 ID 並附上原因，最多兩輪。
4. **合併驗證後保存**，和其他版本相同。失敗時重跑沿用骨架與已填好的國策；最終驗證失敗時保留骨架，只重新填寫。

**國策之間的關係（v0.12.1，取代 v0.12.0 的制衡數量下限）**：使用者與 GPT 參考 Kaiserreich 後，把「互相制衡」擴大為國策之間的因果關係。

- **兩個新規則元件**：
  - **「必須沒有」的條件**：能力或事實條件可以要求「沒有」，例如「承諾：保障地方分成」仍有效時，不能推「清查封地帳冊」。
  - **條件式成果**：完成時條件成立才生效，例如「擴建行省學院」在中央路線給「跨省官僚」，在自治路線給「地方專才」。條件只判定一次；詳情頁會標出「已生效」或「條件未成立，未生效」。
- **核心分支**：骨架標出唯一一支核心分支（本國最主要的戰略問題所在，不限政治）並寫理由。核心分支必須透過「會改變選擇」的關係（能力條件、必須沒有、條件式成果、數值門檻或互斥；單純的前置不算）影響至少 2 支其他分支。
- **其他分支**：原則上參與至少一條跨分支關係；確實可以獨立推進的分支，寫明在本樹的時期與議題內為何獨立。標為獨立就不能同時參與跨分支關係。
- **關係表**：每條寫出兩個國策、關係類型（利益交換、政策配合、機會成本、情境差異、延後兌現、制度替代）與「選了之後，對方的哪些選項、收益、代價或時機會改變」。程式自動找出實現它的規則；找不到就退回。關係表存進國策樹，樹圖右下「⇄ 關係」可以查看，點國策名稱會定位。
- **撤銷能力**保留，用於廢除制度、終止條約、撤回授權，並保留卡死檢查；「有意關閉一條路線」請用互斥。
- **v0.12.2 修正（GPT 審查）**：「沒有 K 才能建立 K」可以通過；注定走不通的「必須沒有」條件（撤銷者只在它之後、或與它互斥）與同一國策同時要求有與沒有的條件會退回；獨立分支改以實際規則判斷，不能和其他分支有能力或互斥的連結（共同起點前置、穩定度與戰爭支持度不算）；重大改樹會移除指向已刪國策的關係，改寫的國策在關係上標示「改樹後未重新驗證」；歷史承接的條件式效果顯示「實際效果未記錄」；關係視窗改用 ↔，方向以規則說明為準。
- **v0.12.3 修正（GPT 第二輪審查）**：獨立分支的跨分支前置只能是共同的起點國策（沒有前置的國策），不能等別支中後期的政策；「必須沒有」條件的撤銷者，要能在不完成受阻國策、也不鎖掉它路線的情況下先完成（例如撤銷者的擇一前置裡，唯一繞過受阻國策的那條走了互斥的另一條路線，會被退回）。
- **相容性**：用本版生成的新樹含有關係表等欄位，**v0.11.1 無法讀取**；v0.11.1 生成的舊樹，本版照常可讀。

**請求次數（每批 25 項）**：標準約 1＋2–3 次，大型約 1＋3–4 次，超大型約 1＋5–6 次，加上可能的補填。每批 40 項時大型約 1＋3 次。

**設定**：骨架版的任務設定（提示詞串、任務預設）另外保存；第一次載入時會複製 v0.11.1 的設定。API 金鑰兩版共用。

**任務預設**：請匯入 `presets/織界國策-任務預設-v3-骨架版.json`，生成思維已改為 skeleton／fill 階段並加入制衡步驟。v1、v2 預設不適用於本版，已從本資料夾移除。

**流式傳輸（v0.12.4）**：API 預設新增「流式傳輸（stream）」開關，預設關閉。開啟後請求以串流送出、邊收邊組合，完成後仍整份驗證。用於前面有 Cloudflare 約 100 秒限制的反向代理（錯誤碼 524），或代理提供「假流式」時。自訂 URL 的請求送出 `stream: true` 並讀取酒館 ChatCompletionService 的串流；沿用酒館連線或代理預設時以 generateRaw 的 `should_stream` 串流。代理回傳 HTML 錯誤頁時，錯誤訊息改為「反向代理逾時（Cloudflare 524）」等可讀說明，不再顯示整頁 HTML。

**骨架修正（v0.12.5）**：大型樹的骨架常因筆誤或數量不足被整份退回、整份重寫，重寫又冒出新錯。本版改為四層處理：
- **格式規則段**：任務指示加入骨架輸出格式的硬規則、對照表與完整範例（另附修正與填寫範例）；空欄位可以省略。
- **本機自動修正**：明確的筆誤直接修正，不發請求——分支 id 或簡繁不同的分支名稱（例如「与／與」）、自創的否定條件 kind（`not_capability` 等改為 `negate:true`）、條件或國策裡多寫的 label／description 等、互斥缺少 lock（補 complete）、中文或大小寫不同的關係類型（「利益交換」→ exchange）。
- **一次列出所有問題**：結構檢查不再遇到第一個錯誤就停，最多列出 20 項；國策數不足不會擋住其他檢查。
- **局部修正**：骨架有問題時不重寫整份，而是把骨架與問題清單交給模型，只回傳 JSON Patch 操作（insert／replace／remove，國策以 id 定位）；數量不足以 `insert /nodes/-` 補上國策。最多 3 輪；3 輪後仍有問題時不保存，但保留目前的骨架，下次重跑從它繼續修正。
- 執行面板的失敗訊息改為可換行顯示完整的問題清單。

**聊天世界書（v0.12.6）**：國策資料改用工作流助手／addon-mvu 的方式提供給正文。
- 每次保存時，腳本在樓層變量 `国策.prompt` 存一份正文用資料：各國概況，以及每國的目前國策與描述、近期完成的國策與描述、現行制度與成果、承諾、相關消息。
- 腳本在**本聊天的世界書**建立「國策檔案-」條目，位置都在「角色定義之後」：
  - 藍燈「世界概況」，順序 99990；
  - 藍燈 `<國策動態>`、`</國策動態>`，順序 99991、99993；
  - 每國一個綠燈條目，順序 99992，劇情提到國名或關鍵字才帶入。
- 條目內容是 `getvar('国策.prompt…')` 的 EJS 模板，送出時才讀取當前樓層的變量，所以切換 Swipe 或回到舊樓層會自動對應。
- 條目只在國家增減、關鍵字或內容模板改變時才改寫。位置、順序與啟用狀態只在建立時設定，之後保留玩家的調整；玩家自己加的關鍵字也會保留。
- 需要提示詞模板擴展（ST-Prompt-Template）；未偵測到時，或在設定中選「直接注入」時，改用原本的注入方式，並移除腳本建立的條目。
- v0.12.6 以前保存的樓層沒有 `国策.prompt`，會先用注入，下一次保存後改由條目提供。沒有任何國家的聊天不會建立世界書。
- 新生成的樹多了 `keywords`（簡稱、首都、統治者、代表地名，最多 8 個），作為綠燈關鍵字；舊樹只用國名。
- 本版也移除了任務預設的國運籤與時局籤。執行紀錄的每筆請求會標出階段，例如「修正骨架（第 1/3 輪，5 個問題）」。

**刪除迷霧（v0.12.7）**：迷霧功能已移除。迷霧會讓正文看不到 AI 國已完成但未公開的國策，於是把已經發生的事寫成還在醞釀。現在面板、國策快訊與正文資料都呈現實際狀態：
- 未公開的國策與事件在正文資料中標示「未公開」，提示詞說明只有該國高層、當事方與知情者知道，也不可把已完成的事寫成尚在醞釀。
- 移除了面板的「迷霧 開／關」、國家列的「完整觀察」與一般設定的「啟用國策迷霧」。
- 事件的 `public` 與國策的公開紀錄（publications）保留，改作為上述標示的依據。
- 存檔仍保留 `settings.fog`／`observing` 欄位（不再使用），讓 v0.11.1 仍可讀取。

**正文承接修正（v0.12.8，GPT 審查）**：
- 持續事件以最新進展呈現，例如「起因：港口實施禁運。最新進展（今日）：協議生效，禁運已解除。（始於 90 天前，已結束）」。近期消息依最後更新日挑選；國家詳情先列仍在發展的事件。
- 推進中但未公開的國策也標示「未公開」。
- 正文資料說明：國策描述是推動時的計畫，實際結果以完成狀態、制度、承諾與最新消息為準；穩定度與戰爭支持度只是輔助指標。
- 世界書模式下，腳本仍先直接注入，等本聊天的條目確認就位後才撤掉注入。同步失敗時保留注入，並跳出一次提示。
- 世界書工作綁定排入時的聊天與樓層：切換聊天、Swipe、刪除或編輯樓層後，舊工作不再寫入；同一聊天只有最新的一次會寫入。
- 工作流助手的「世界局勢」任務只讀角色世界書，讀不到聊天世界書。請改用下方 v0.12.9 的 EJS 提示詞段落。

**各國詳情改為完整歷史、預設藍燈（v0.12.9）**：比照工作流助手世界狀態的原則：進行中的完整呈現，歷史精簡但不遺漏。
- 各國詳情包含：
  - 推進中的國策與描述；
  - 已選定路線；
  - 轉折國策與最近 4 項完成國策的描述；
  - 全部已完成國策的名稱，依分支、由早到晚排列；
  - 全部現行制度與成果；
  - 承諾；
  - 相關事件：仍在發展的事件逐條列出完整脈絡，已結束的只列最近 2 則的起因與結局。
- 一般設定新增「各國詳情條目」：
  - 預設**藍燈**，每次都送出，正文不會遺漏遠方國家的變化；
  - 可改為綠燈，提到國名或關鍵字才送出。
  - 這只影響正文看得到什麼，各國國策的推進由局勢更新任務決定，不會因為沒被提到而停滯。
- **讓工作流助手的「世界局勢」讀到國策**：它的每個提示詞段落都會跑 EJS，讀取該樓的變量。在「世界時局與經濟簡報」任務新增一個提示詞段落，貼上以下內容。這樣不必動任何世界書，也不影響其他聊天：

```
<國策動態>
<%- getvar('国策.prompt.overview', { defaults: '' }) %>
<%_ const nf = getvar('国策.prompt.countries', { defaults: {} }); _%>
<%_ for (const id in nf) { _%>

<%- nf[id].text %>
<%_ } _%>
</國策動態>
```

  兩個背景工作的先後不固定：國策先保存完，世界局勢就讀到本樓的新狀態；世界局勢先跑，讀到的就是上一次保存的狀態。

**重試（v0.12.10）**：
- 任務的「每條連線重試次數」上限由 3 提高到 10。
- 分段生成時，骨架修正也套用任務重試：
  - 每次嘗試最多修正 3 輪。重試次數為 N 時，共有 N＋1 次嘗試，也就是最多 3×(N＋1) 輪。
  - 一次嘗試結束後，問題數有減少就繼續修正；沒有減少就重新生成骨架，並把仍無法解決的問題（previousProblems）告訴模型。
  - 全部用完才失敗，重跑時從最後的骨架繼續修正。
  - 執行紀錄標題顯示「修正骨架（第 a/N＋1 次，第 i/3 輪，n 個問題）」。

**尚未用真實 API 驗證。** 下面各節的「藍圖」「逐段」「補寫」說明屬於 v0.11.1，本版保留作為紀錄。

## 國策事件與國際快訊（v0.9.0）

參考鋼4 的新聞事件與工作流助手「自動化系統」「資產賬本」的正則美化：

- **轉折國策**：生成時每支分支需要 1–2 個會讓世界做出反應的重大國策（宣戰或最後通牒、併吞、改制、結盟或廢約、重大超凡力量的動用），樹圖上以 ✦ 標示。完成時自動發布一則新聞事件，內容來自國策的 `news`（頭條、內文、唯一選項）。
- **局勢更新的事件**：每筆事件分前台（與正文或玩家國直接相關）與後台（鏡頭外），有重要度、頭條、狀態（進行中／已結束）、結算條件與唯一選項；選項效果寫在 changes，可以沒有效果，提交時即生效。進行中的事件之後用 `eventUpdates` 逐期推進，直到結算。每國進行中的前台事件最多 3 件、後台最多 5 件；已結束的事件保留最近 60 件。

- **正文卡片**（v0.13.0 起改為報紙版快訊條，見上方）：有新聞的 AI 樓層末尾會自動加上 `<国策快讯/>`。在酒館「正則」匯入 `dist/國策快訊-卡片正則.json`（只影響顯示、只渲染最近兩樓），標籤會變成一張摺疊的「國際快訊」卡片，可展開頭條，或按「開啟新聞」叫出上面的視窗。建議同時匯入 `dist/國策快訊-提示移除正則.json`，讓標籤不送給模型，避免模型模仿輸出。標籤不算正文編輯，不會讓任務過期。

## 國策樹檔案：匯入與匯出（v0.8.0）

「管理國家」上方的「國策樹檔案」：

- **匯出**：每國一列的「匯出」，或「匯出全部」「複製全部 JSON」。檔案含國策樹定義（tree）、目前進度（status）與涉及該國的事件（events），適合回報問題與備份。含完整資料，分享前請留意劇透。
- **匯入**：選擇檔案後先顯示預覽（國名、id、國策數、分支數、是否含進度、是否取代現有國家），確認後才寫入目前樓層。
  - 預設只匯入定義，國策全部從未開始（`historical` 列出的除外）。
  - 勾選「連同進度」時保留檔案中的進度、能力、承諾、事實與鎖定，並從目前故事日重新校準，匯入後請執行「更新局勢」。事件不匯入。
  - 同 id 的國家已存在時，必須勾選「取代」才能匯入，原有國策樹與進度會先刪除。
- **下載範本**：一棵四項國策的合法範例，示範所有欄位、前置、互斥與能力條件，可複製改寫成 submod 或手寫國策樹。

匯入的檢查與 AI 生成不同：**不限規模、不要求分岔／匯流數量**，但必須能遊玩：格式正確、ID 唯一、前置存在且無循環、每個互斥組至少兩條路線、每條路線可達、能力條件有來源。錯誤訊息會指出國策 id 與欄位。

手寫時可以省略的欄位：`x`／`y`（一律重新排版）、`icon`（預設 crown）、`reason`、`durationReason`、`requirements`／`sustain`／`outcomes`／`investments`／`effects`（預設空）、`mutex`（預設 null）；國家層的 `description`、`stability`／`warSupport`（預設 50）、`evidence`、`analysis`、`branches`、`capabilities`、`historical`。前置可寫成 `[["a","b"],["c"]]`（a 或 b，且 c），也接受 `["a","c"]`（兩者都要）與 `[[{"id":"a"}]]`。

接受的檔案形式：本擴展匯出的 `{"kind":"national-focus-tree","version":1,"countries":[{"tree":{...},"status":{...}}]}`、單一國策樹物件，或國策樹陣列。

## 刪除國策樹（v0.7.0）

「管理國家」中每個已建立的國家都有「刪除國策樹」，按下後在同一列確認。刪除會移除該國的國策樹、進度、能力、承諾、事實與觀察設定；只涉及此國的事件一併刪除，與他國共同的事件保留給其他國家。刪除寫入目前樓層的 MVU；較早的樓層仍保有舊資料，切回舊樓層或重新生成回覆時會看到當時的狀態。刪除後該國回到候選清單，可直接勾選重新生成，不必再辨識一次。有任務執行或排隊時按鈕停用，避免與背景任務的寫入衝突。

## 匯入酒館

1. 在酒館助手的腳本庫匯入 `dist/國策檔案-骨架版-酒館助手.json`，啟用腳本（並停用 v0.11.1 的腳本）。原始單檔程式另見 `dist/national-focus.js`。
2. 同時啟用 MVU 變數框架，切到一則已有 `stat_data` 的完整 AI 回覆。
3. 點獅鷲懸浮球 → 設定。確認「世界書與上下文」的故事時間路徑；預設 `世界.时间`，相對於 `stat_data`。
4. 時間欄位支援 `复兴纪元490年-10月-15日-星期三-14:25`（也接受「復興紀元」）、非負數值日序、`YYYY-MM-DD HH:mm`、`YYYY年M月D日`。紀元年月日沿用既有公曆月份與閏年規則計算日差，保留時分；星期只作格式辨識，不用現實曆法校正故事星期。不修改原時間文字。未辨識的曆法、空值或「隔天早晨」不會被猜測為時間；請映射至一個可靠的數值日序欄位。
5. 在「API 連線」新增或編輯預設，填 OpenAI 相容 URL、金鑰與模型；可「載入模型」後從清單選擇，也可手動輸入模型。按「保存目前預設／保存並選中預設」獨立保存，不需要 MVU 就緒。URL、模型與代理皆留空時沿用酒館目前連線。預設輸出上限 **60,000 token**、Temperature **0.85**，也套用於目前酒館連線；舊設定保留已保存數值。已移除測試連線按鈕。
6. 在「管理國家」辨識候選國家，勾選要啟用者。可先選小型樹試用，再改標準／大型／超大型。
7. 後續每次正文完成預設更新局勢。首次生成、重大改樹預設手動，避免反覆生成或大幅修改。逐國可切換玩家／AI、跳時代選與啟用。

v0.3.0 起，API 金鑰與 Authorization／X-Api-Key 類標頭依工作流助手做法**不再存於 localStorage**：改存酒館擴充設定（`extensionSettings.__userscripts`，隨酒館帳號保存並由酒館寫入 settings），並以 IndexedDB 備份。其他 API 預設、來源與排程偏好同時保存到酒館擴充設定與此瀏覽器 localStorage，所以換瀏覽器登入同一酒館也會帶著設定。舊版存在 localStorage 的金鑰會在第一次載入時自動搬移並從 localStorage 移除。酒館設定同樣是未加密的伺服器檔案；找不到酒館擴充設定時才退回 localStorage，API 頁會標示實際位置。規模、節奏、迷霧、觀察國家與完整國策狀態保存在樓層 MVU。憑證不寫入樓層變量、劇情、執行紀錄或交付的匯入檔。

## API 預設

- 對照工作流助手的 API 頁面提供（v0.3.0 以 GitHub 最新原始碼，約 v0.0.46，重新核對）：目前聊天預設選單、★ 全域預設、新增、刪除確認、改名、獨立保存與放棄修改。任務的「跟隨目前聊天預設」使用聊天選擇，未指定聊天時使用全域預設；明確指定的主要／備援連線仍優先。改名會同步引用；刪除會清理引用，至少保留一份。
- 模型手動輸入與下拉清單並存。「載入模型」使用酒館助手 `getModelList`，只取得模型清單、不送出生成請求；無清單時仍可手動填寫。离線 UI 頁不連 API。
- 提供最大回覆長度、Temperature、Prompt 後處理（none／strict）、附加主體 YAML、排除主體參數、附加請求標頭、include_reasoning 與推理強度。進階選項需要明確 URL／模型，不能搭配酒館代理名稱。
- 「嚴格 JSON 回應」（v0.13.3 起只在這裡設定）：開啟時加入 `response_format: json_object`、strict 後處理，並排除 `top_p`／`reasoning_effort`；關閉只移除 `response_format`，其他附加參數保留。「一鍵 DeepSeek 結構化輸出」與還原、DeepSeek COT 開關另外提供，COT 調整 `thinking` 與 `include_reasoning`。
- 明確 URL 的請求優先經酒館 `ChatCompletionService.processRequest`，與工作流助手同樣傳入擴充參數，不修改酒館全域預設。服務不存在或呼叫失敗時，只有基本參數會回退 `generateRaw`（與工作流助手相同）；使用附加主體、排除主體、標頭、strict 後處理或推理參數時不回退，並明確報錯，避免靜默省略。
- 回應解析同時接受酒館擷取結果、OpenAI `choices` 與純文字，並把 `reasoning`／`reasoning_content` 與正文分開；推理只進執行紀錄，不參與 JSON 解析。JSON 解析會移除代碼圍欄、`<think>` 類標籤與前後說明文字，只取完整的最外層物件；截斷或不合法的物件仍算失敗，不做修補。
- 預設內容的修改按 API 分頁底部的「保存預設」保存，視窗不關閉（v0.13.4）；頁尾「儲存設定」也會一併保存。選擇、新增、刪除與設為全域預設立即生效。有未儲存修改時切換預設會先詢問。離線頁保存僅留在本頁記憶體。

## 世界書與上下文

v0.2.5 依工作流助手 v0.0.38 的來源處理重做；v0.3.0 再對照最新原始碼（約 v0.0.46）補齊佔位符來源與掃描細節。舊版把啟用的全域／角色世界書、未提取的近期訊息與預設整個「世界」MVU 一起傳入，可能造成極大的輸入；現在先篩選與提取，再組成工作請求。

- **世界書（$1）**：角色主書＋附加書，或手動選擇多本；不自動載入全域書。可搜尋、勾選個別條目、全選啟用條目、全不選。手選空白與空條目清單都代表不選；可明確勾選酒館停用條目，不修改原世界書。
- **觸發與過濾**：常駐條目直接納入；綠燈主關鍵字掃描提取後的 AI 正文、選用的使用者輸入、補充工作文字與提示詞段，最多遞迴 10 輪。第 0 層只看上述文字，條目正文只作為遞迴來源；遵守「禁止遞迴激活他人」（prevent_outgoing）、「防止被遞迴」（prevent_incoming）與 `delay_until`。過濾規則／MVU／工作流托管及專用紀要條目；表格匯出只保留表格本體。這是工作流助手的主關鍵字掃描方式，不是酒館完整的次關鍵字、機率及 Regex 執行器。
- **輸出格式**：與工作流助手最新版相同，只送條目正文、不帶條目名稱；依 before／after 角色定義、depth、order 與原始順序排列。放進提示詞段時 $1 以 `<worldbook_context>` 包裹、$2 以 `<worldbook_extra>` 包裹。
- **資料庫表格**：工作流助手會把 TavernDB-ACU 表格匯出（紀要、主角資訊、托管條目除外）一律放入 $1。這裡預設仍受勾選限制；開啟「資料庫表格條目一律納入」才採用該行為。
- **條目清單**：切換角色／手動選書或勾選世界書時自動重新載入，依世界書分組顯示已選數量；已不存在的條目 UID 會從保存的勾選中移除。未手動調整的世界書沿用酒館啟用狀態，不會因為開啟面板就被凍結成固定清單。
- **上下文（$7）**：預設最近 3 則 AI 回覆，包含當前樓並使用目前 Swipe；0 表示僅當前樓。預設不送使用者訊息。可在「任務」分頁把某項任務的世界書或上下文改成「此任務自訂」（v0.13.3 起取代兩個全域開關），自訂存在就生效，其他任務沿用預設。
- **提取／排除規則**：每條填開始詞與結束詞，先提取再排除；不分大小寫、只取最後一組完整邊界，支援 `<content`／`<tp` 開標籤前綴。保留提取邊界，多條結果按規則順序合併；完全未命中時保留原文，預覽會標出。每條排除規則只刪最後一組，也套用於合併後世界書。
- **記憶回溯（$6）**：預設從預設世界書取最近 10 條 AM 紀要，按時間排列，包裹不占數量；0 關閉。與劇情條目勾選分開。
- **使用者輸入（$8）**：預設關閉。與工作流助手相同，只取當前 AI 樓的前一樓（且必須是使用者訊息）；優先取名稱含「输入／輸入／input」的最後一個標籤內文，否則刪除「以上是用户的本轮输入」等模板行之後的內容，再移除 `(⚠️:…)` 預設提醒。
- **其他來源（預設關閉）**：$2 角色綁定世界書的 `WorkflowHelper-*` 托管條目（只取酒館已啟用者，按同一掃描規則）；$5 紀要索引條目，沒有時改讀資料庫插件的紀要表或總體大綱；$U 酒館 persona 描述加上「主角信息」匯出條目；$C 目前角色描述。都會經過巨集／EJS。
- **巨集與 EJS**：依工作流助手流程：酒館助手巨集開啟時用 `formatAsTavernRegexedString`（含酒館正則，深度＝最新樓層減來源樓層），關閉時只用 `substitudeMacros`；有 `<%` 才執行 EJS，之後再跑一次巨集。EJS 失敗時保留原文並在主控台警告。同一次讀取會共用每本世界書的讀取結果與相同文字的處理結果。
- **MVU**：預設不附帶額外變量。故事時間照常在本機讀取，國策自身必要狀態由各工作組裝；只有明確填寫的額外 MVU 路徑才列入來源。巨集／酒館世界書正則與可用的 EJS 在已選且觸發條目上處理，再計算來源大小。
- **預覽與上限**：「預覽將送出的來源」不呼叫 API，可查看每則 AI 提取前後、各條目是否納入、各區塊字元數及實際來源。完整工作會再計入系統提示、Schema、國策狀態與重試回饋；預設 **120,000 字元**，超過就停止，不截斷、不重試或切備援。上限可以修改，字元數不是 Token 數，供應商用量仍以實際回報為準。

提取規則預設空白，不猜測玩家的正文標籤。預覽會逐項列出 $1–$C 的字元數與位置（JSON／提示詞段／未開啟），以及各提示詞段展開後的內容。例如正文使用 `<content>…</content>`，可新增開始詞 `<content`、結束詞 `</content>`；若正文是其他標籤，應填實際邊界。先載入條目、調整規則、預覽，再按頁尾「儲存設定」。來源設定可以保存，不需要 MVU 就緒；來源預覽與正式工作則需要有效的目前 AI 樓層及故事時間。

升級會保留明確選書／條目、額外要求與故事時間路徑，將舊版上下文數量縮到最多 3 則 AI，並清除旧預設 `世界` 整包變量；其他明確設定的 MVU 路徑保留。v0.3.0 新增的來源都預設關閉，升級後請求內容只少了條目名稱。請先確認預覽再恢復自動工作。

未移植的工作流助手功能：多任務流程與階段、任務結果標籤變量（`{{標籤名}}`、副本族、`{{total:…}}` 等巨集）、世界書寫入規則、正文標籤替換、AI 樓層／使用者輸入文末注入、聊天級任務快照、工作流預設匯入匯出，以及變量 JSON Patch 結構化模式。這些屬於工作流助手的任務引擎；國策腳本的輸出固定是經本機驗證的國策 JSON。

## MVU 與分支規則

- 國策資料保存在樓層變量最外層 `国策`，不放進 `stat_data`，不新增或修改角色卡的 Zod／MVU schema。故事時間與設定的世界變量來源仍相對於 `stat_data`。
- 舊版 `stat_data.国策` 可相容讀取；下一次成功保存或一般 MVU 更新時，將當前回覆的資料移到最外層並移除內層副本。若兩處都有資料，以最外層為準；無效資料會報錯。歷史樓層不批次改寫，舊 schema 定義保持原樣。
- 一般 MVU 更新完成時保留更新前 `国策` 區域，國策腳本獨立驗證後提交。注入的正文提示也要求一般變數模型勿修改此區域。
- 只寫來源聊天的最新有效 AI 樓層及其當前 Swipe。新正文開始、換聊天、换 Swipe 或變數改變後，舊結果不會寫入新樓，也不回頭改祖先。
- 保存正文依據的 SHA-256。早期正文被編輯後，舊國策依據不匹配會明確報錯；須從受影響處重生成或分支，不能宣稱後代已自動修復。
- 玩家操作涉及進度或交接時，若故事時間已有尚未處理的落差，需先執行「更新局勢」。這不攔截續聊，也不會將剛開始的國策倒填到过去。
- 國家重新啟用時等待 AI 現況校準，不補造停用期間歷史。成果失效只改能力，保留完成紀錄。效果、事件與提案 ID 用於防止重複結算。
- 跳時按步驟時間推進；模型必須給出各事件時點及代選順序。取消或失敗不提交半套提案，可按目前有效樓層重新計算。
- v0.12.7 起沒有迷霧：面板與正文資料都呈現各國的實際狀態，未公開的國策與事件只加上「未公開」標示，由正文依角色的身分與處境決定誰知情。

## 四種任務與 API 邊界

固定提供四項任務：國家辨識、國策生成、局勢更新、重大改樹。更新與改樹可按回覆、N 則正文、N 故事日或手動排程。初次生成由玩家勾選觸發。每項任務有主要連線、按順序故障切換的備援、有限重試、取消與逾時。

### v0.5.0：任務頁、提示詞串與任務預設（對照工作流助手「任務」）

- 設定中的「背景工作」改名為 **任務**。頁面上方是**任務預設**列，下方以四個分頁切換任務，每項任務有三塊：API 路由（主要連線與逐條備援，各有並發上限）、執行設定（觸發方式、間隔、重試、逾時；v0.13.3 起嚴格 JSON 移到 API 預設，另加每批國策數與建議模型）、**提示詞串**。
- **提示詞串**：每項任務實際送出的完整訊息序列，可逐段閱覽、開關、修改名稱／角色／內容、上下排序、新增或刪除自訂段，並可「預覽完整提示詞串」（依目前草稿組出實際訊息，不呼叫 API）。內建三段：
  - 系統規則（system）：原本寫死在程式裡的共同規則。
  - 任務指示（system）：該任務的專屬指示；生成任務的節點數、分支數與字數上限以 `limits.*` 引用資料中的數值。
  - 任務資料（user）：`{{data}}` 會換成本次 JSON（任務種類、Schema、故事日、國家狀態、來源、重試回饋）；缺少 `{{data}}` 時 JSON 接在最後。此段不能停用。
- 內建段未修改時跟隨新版預設文字；修改後標示「已修改」，可「還原預設內容」，清空也會恢復預設。

- **內附任務預設** `presets/織界國策-任務預設.json`：參考工作流助手「世界後台引擎」預設的結構編寫（織界核心、國策風格包、國運籤、分步思維要求、背景信息、收尾訊息），內建三段保持預設並包在「國策律」中。風格包預設開啟制度深耕、派系權謀、超凡威懾，其餘七包可在提示詞串中自行開關。國運籤／時局籤需要酒館的提示詞模板（EJS）擴充；沒有時籤池以原文送出，請關閉該段。思考寫在原生思考或 `<thinking>` 內，解析前會移除，因此此預設的四項任務都關閉嚴格 JSON。此預設不含世界書與上下文設定，套用時保留目前的來源選擇。
- **進度小窗**：任務進度不再用設定內的二級面板，而是懸浮球正上方的小視窗（懸浮球在畫面上半部時改到下方）。顯示執行中／排隊的任務、國家名稱、目前步驟與耗時；完成後約 6 秒、失敗約 20 秒自動淡出，也可手動關閉。標題列有「停止」（取消全部）、「紀錄」（開啟任務紀錄）與收合。拖曳懸浮球或小窗標題列都會一起移動，位置與收合狀態保存在此瀏覽器的 localStorage（`national-focus.orb.v1`），不可用時只在本頁保留。刻意不放在右上角，避免與工作流助手的進度框重疊。

模型輸出經 Zod 與國策規則檢查後才能提交。不接受 JavaScript 或任意 JSON Patch。生成會驗證 ID、無循環前置、格點、數量、歷史承接及效果。局勢更新會驗證時間順序、一國一主國策、互斥、成果條件、跨國變更、權限與舊節點不可改寫。

## 大型樹的生成方式

**v0.11.1：寫少不重試，最後才補寫。** 某段寫得比藍圖規劃少時，直接保留，不再為了數量重寫整段。所有段完成後，全樹若低於規模下限，才發補寫請求，只補缺少的項數（每次最多「每次最多國策數」項，不夠再補一次），優先補在缺最多的分支。某段寫太多時，只要後面每段還有名額也保留（最多約規劃數的 1.25 倍）。其他規則（前置、互斥、轉折國策、分岔與匯流）不符時仍會帶著原因重試該段。

**v0.13.3：「每批填寫國策數」移到生成任務的執行設定。** 沒改過時沿用下面所說 API 預設上的值。

**v0.11.0：每次最多國策數可調。** API 預設新增「每次最多國策數（分段生成）」，可點 15／25／40／60／不限，也可直接輸入數字（0 為不限）。生成國策樹時使用生成任務的主要 API 的值（未指定時用目前聊天的 API 預設）。數值越大，請求越少，但單次輸出越長，越容易截斷或逾時。改變此值後重跑，不沿用舊藍圖。

**v0.10.1：段數合併。** 模型常把每條互斥路線切成獨立的段（實測大型樹 6 支切成 16 段）。現在單段上限提高到 25 項，程式在藍圖回來後把同一支的相鄰段合併到 25 項以內，所以一支不超過 25 項時只發一次請求。

**v0.10.0 起：分支少而深。** 所有規模都只有 3–6 支分支，規模越大，分支越深、互斥路線越多，而不是分支越多。理由：一國同時只推進一個國策，一段 RP 通常只完成十幾到二十幾項；分支太多時大多數走不到、選擇變輕、轉折國策被稀釋，每支也容易被灌水。

| 規模   | 全部路線合計節點 | 分支數 | 每支約 | 請求次數（藍圖＋各段） |
| ------ | ---------------- | ------ | ------ | ---------------------- |
| 小型   | 15–25            | 3–5    | 4–7    | 1（單次）              |
| 標準   | 40–60            | 4–6    | 8–15   | 約 5–7                 |
| 大型   | 70–100           | 4–6    | 12–25  | 約 5–9                 |
| 超大型 | 110–150          | 5–6    | 18–30  | 約 8–13                |

分支結構的建議：一支國體或政治路線（內含 2–4 條互斥路線，是全樹的核心抉擇）、一至兩支對外、一至兩支內政，必要時一支專屬分支。藍圖把每支分成 1–4「段」（每段 3 項到「每次最多國策數」，預設 25），之後每段一次請求。一支不超過 25 項時只用一段；v0.10.1 起，模型若把同一支切得太細，程式會把相鄰的段合併到 25 項以內，請求數不會因模型的切法而增加。分支數超出範圍時，藍圖會被退回並說明原因。

這是全樹內容量，包含互斥路線；單次遊玩不會完成所有節點。規模設定只影響新生成的樹；已生成的較大國策樹照常可玩，不會被裁減。

以下為 v0.6.0–v0.9.0 的分段說明；v0.10.0 起「逐支」改為「逐段」，分岔、匯流、轉折國策與互斥路線的落實改在該支最後一段檢查，其餘規則相同。

**v0.6.0 起，標準以上的規模改為分段生成。** 使用者實測多個常用模型，單次回應都寫不出 60 項以上，因此：

- **小型（15–25）**：維持每國一次請求，一次輸出完整樹。
- **標準、大型、超大型**：
  1. **藍圖**：一次請求輸出國家資料、analysis、初始能力、各分支（加上預計國策數 quota 與發展順序 outline）及互斥路線規劃 choices。本機檢查分支數、quota 合計是否落在規模內、互斥組是否指向存在的分支。
  2. **逐支生成**：每支一次請求，資料中附上藍圖、已生成的國策清單 existing（ID、名稱、互斥、提供的能力）與本支允許的數量範圍 range。前置只能引用本支或已生成的國策；第二支起至少一條跨分支依賴；每支至少一處分岔與一處匯流（範圍至少 5 項時）；藍圖指派給本支的互斥路線都要落實。每支回來後，本機立即對「目前為止的整棵樹」檢查缺失引用、循環、路線可達與能力順序，錯誤原因回饋給模型重試該支。
  3. **合併**：全部分支完成後，本機合併，再跑與單次生成完全相同的整樹驗證，通過才寫入 MVU。
- 請求數約為「分支數＋1」，例如標準 6 支約 7 次。每支都能使用完整的文字字數（描述 120、理由 60、工期理由 40 字），不必再為了塞進一次回應而壓縮。
- 某一階段在重試與備援後仍失敗時，不保存半棵樹；**在同一樓層、同一來源下重跑，會沿用已完成的藍圖與分支，只補剩下的**。若合併後的整樹驗證失敗，則下次從藍圖重新開始。生成期間繼續聊天會以生成事件取消舊工作，已完成的階段也不再沿用。
- 內建「任務指示」依資料中的 stage（generate／blueprint／branch）說明各階段要輸出的內容；未修改內建段的提示詞串會自動採用。

v0.6.0 另外在驗證前做本機形狀修正：前置寫成物件（例如 `[[{"id":"a"}]]`，Gemini 常見）、平鋪陣列 `["a","b"]`（視為兩者都要）、`{"any":[...]}` 群組、缺少陣列欄位或空的 mutex，都會改成規定格式再驗證。

v0.6.1：每個互斥組至少要有兩條路線，否則退回重寫。樹圖上 ⇋ 只標在路線的起點（同一路線的後續國策不再重複標示），互斥線連接各路線起點且不穿過卡片；點選國策時，詳情會列出與它互斥的其他路線。

以下為 v0.2.1–v0.5.x 單次生成時期的說明，小型規模仍適用：

**每個國家一次呼叫生成完整國策樹。** 國家分析、3–16 個分支、全部節點、前置、互斥、效果及歷史承接在同一份 JSON 回應中完成。經世界書與上下文規則整理後的來源、額外要求與候選國家一起傳入，後續不再拆成分支、細節或 AI 審查請求。移除舊版每批 12 項與每支 30 項限制，全樹上限仍為 300。

國家分析與分支的目標、支持者、反對者、取捨、終點一起存在 MVU，詳情面板可查看分支取捨。座標由程式依前置深度、分支區域與同列位置產生，不要求模型直接排好大型畫布。顯示布局也會依目前圖結構重算，收合與平移不改寫遊戲進度。

v0.4.1 修正生成反覆重試：

- 重試時把本機驗證的具體原因（例如「生成規模須為 120–200 節點，本次只有 27 項」、JSON 被截斷）回饋給模型，並顯示在任務進度與任務紀錄；供應商錯誤仍不回饋給模型。生成與辨識的失敗原因在迷霧下也顯示。
- Schema 為 requirements／sustain／outcomes／effects 加上說明：outcomes 是完成前必須取得的外部成果，不是本國策的產出。
- 本機修正兩種明確失誤，不必再花一次完整請求：條件引用本國策自己產出的能力且沒有其他來源時移除（outcomes 重複自身產出一律移除）；只有歷史國策產出、後續國策需要、卻漏列在 capabilities 的能力視為仍有效。沒人需要的漏列能力照舊視為已失效。
- 生成提示依規模給出建議分支數、每支項數與各欄位字數上限，並要求壓縮 JSON。實測一個約 1,400 字元的節點，120 項需十幾萬字元輸出，常超過單次輸出長度；精簡後才可能一次容納。模型仍只給出少量節點時，請改用較小規模或提高輸出上限。

正常成功時，1 國為 1 次生成請求，3 國為 3 次，300 節點也不另拆批次。只有 API 失敗、輸出截斷、格式或國策規則不符時，才依「國策生成」的既有重試與備援設定再次請求完整樹。事前的「辨識國家」是另一項工作，不計入各國生成次數。沒有自動局部修正或額外 AI 審查。

新設定及新增連線的輸出上限預設 60,000 token；新設定的國策生成逾時為 600 秒。升級保留已保存的 Token、逾時與重試設定：若舊連線仍為 16,384 或生成逾時仍為 180 秒，可在設定中改為 60,000／600。這是請求上限，不是保證輸出長度，也不會強制每次用滿六萬 token。

腳本在本機驗證完整回應，包括節點數、分支引用、前置循環、互斥相容性、能力來源、歷史與效果，再排版並一次寫入來源 MVU。本機檢查不呼叫 API。失敗、取消不保留半棵樹；重新執行會重新生成。多國依序各取來源快照並各自保存，其中一國失敗或取消後停止，先前成功國家保留。

日常局勢更新省略已完成節點的執行內容、全部節點長篇描述、座標及收據歷史，保留未完成節點的前置、效果與條件，讓長時間跳躍仍能選擇後續路線。重大改樹仍取得完整節點定義，提示模型每次聚焦最多 30 個受劇情影響的未開始節點；實際節點總上限為 300。

本機結構檢查能攔截部分重複和死路，世界設定與敘事品質仍由模型及玩家審視決定。真實模型的長樹生成、上下文需求與費用仍待實際酒館驗證。
